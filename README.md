# Paddle Benchmark Suite

`Paddle Benchmark Suite` — набор сценариев для сравнения производительности моделей в экосистеме PaddlePaddle и смежных фреймворках. Репозиторий организован по направлениям (CV, NLP, OCR, Speech, GAN, RL) и по режимам запуска (`static_graph`, `dynamic_graph`, `dynamic_to_static`).

## ✨ Особенности

- Большое количество готовых `run_benchmark.sh` сценариев.
- Поддержка `Paddle`, `PyTorch`, `TensorFlow`, `MXNet` в отдельных подпроектах.
- Разделение по типам графа: `static_graph`, `dynamic_graph`, `dynamic_to_static`.
- Отдельные каталоги под модели и домены (`PaddleDetection`, `PaddleOCR`, `PaddleNLP`, `PaddleSpeech` и т.д.).
- Возможность локальных экспериментов и воспроизводимого запуска через shell-скрипты.
- Масштабируемый формат: для большинства моделей есть единообразная структура папок и скриптов.

## 🚀 Быстрый старт

### 1) Выберите нужный сценарий

Пример: запуск YOLOv3 на Paddle в static-графе.

```bash
cd static_graph/yolov3/paddle
bash run_benchmark.sh
```

### 2) Запуск других сценариев

Аналогично запускаются скрипты в `dynamic_graph/*/*/run_benchmark.sh` и `dynamic_to_static/*/*/run_benchmark.sh`.

## ⚙️ Как подготовить запуск

- Убедитесь, что установлены зависимости конкретного сценария (обычно рядом есть `requirements.txt`, `prepare_data.sh` или `download.sh`).
- Перед сравнением разных фреймворков используйте одинаковые данные и близкие гиперпараметры.
- Для корректного сравнения фиксируйте окружение: версия CUDA/cuDNN, драйвер, версия Python и используемые контейнеры.

## 📁 Структура проекта

- `static_graph/` — сценарии статического графа.
- `dynamic_graph/` — сценарии динамического графа.
- `dynamic_to_static/` — сравнения режимов dynamic vs static.
- `PaddleClas/`, `PaddleDetection/`, `PaddleGAN/`, `PaddleNLP/`, `PaddleOCR/`, `PaddleSeg/`, `PaddleSpeech/` — бенчмарки по продуктовым направлениям.
- `scripts/`, `ci/`, `api/` — вспомогательные скрипты автоматизации.

## 🛠 Использование

- Запускайте нужный `run_benchmark.sh` из целевой подпапки.
- Для конкретной модели обычно рядом лежат доп. скрипты подготовки данных (`prepare_data.sh`, `download.sh`) и запуска обучения/инференса.
- Сравнение между фреймворками выполняется запуском эквивалентных подпапок одной и той же модели.
- Результаты удобно собирать в единую таблицу по latency, throughput и memory.

## 📊 Практический сценарий

Типовой цикл работы:

1. Выбрать модель и режим графа.
2. Подготовить данные и окружение.
3. Прогнать baseline на Paddle.
4. Прогнать эквивалентный сценарий на альтернативном фреймворке.
5. Свести метрики в отчет.
